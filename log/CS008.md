## P1 — the rim fix: (A) + (B) + ε, and 100 % killable at the rim

Built from `PLANNED-FEATURES-CS008.md` §2, on Paul's R1/R2 calls. Nothing
designed here.

**What shipped.** (A), ordering A1: `updateShots()` ages and filters, then
fires, and the `SHOT_MAX` check reads the post-retirement length. (B): the
Vaulter, Carrier, Drifter and Surger climbs clamp at `1 - C.RIM_CONTACT_DEPTH`,
written as that expression in each (never `this.killDepth`, which the Surger
zeroes), and `Vaulter.atRim()` reads the same expression. The `WeaverBolt` is
untouched. (ε): `C.HIT_DEPTH_EPS` 1e-9, in `collideShots()`'s band test only.

**Why four samples now.** A shot moves `DT / SHOT_TIME` ≈ 0.03205 per step, so a
fired shot is tested at 1.000, 0.968, 0.936 and 0.904. All four are within
`HIT_DEPTH_TOL` of 0.95 — but the first only with ε, since `|1 - 0.95|` is
0.050000000000000044. Four consecutive samples against a four-step cadence is
every phase. Without ε, or without (A), it is three of four, which is exactly the
18/24 the mutations below produce.

## P4 (2026-09-13) — text, the HUD and the death fragmentation

**Built to plan §5.** `drawText()` is in `13-render-well.js`, beside

**Implementation choices within the plan, none of them design.**
- **`hudLayout()` is split out and exported.** The plan asks for "HUD rectangles"
  to assert against, so the rectangles are the draw's own input, not a copy.
  The test also checks every drawn path lies inside its rectangle, which keeps
  the two honest.
- **Text rectangles are sized by `C.TEXT_CHAR_W` (0.62 em), not `measureText()`.**
  The headless stub returns width 0, and a monospace advance is at or under
  0.6 em in every font in the stack.
- **The view carries the icon poly and the level colour.** `drawHud` then reads
  only `C`, so it has no `SKIMMER_POLY` or `wellBandColor` reach. The view
  object is module-level in `Game` and filled in place.
- **`fragmentT(left, total)` takes numbers, not `Game`.** That keeps the primitive
  clear of game objects. With `left` 0 (a headless caller that never froze), `t`
  is 1 and nothing is drawn.
- **The Purge glyph is an eight-point burst**, ⚠ provisional art like the
  palette. A 24 px margin, 28 px text and 30 px icons are ⚠ provisional sizes.
  All are `C` constants and judgeable on hardware.
- **`drawText` sets `textBaseline = "top"`**, so a rectangle's `y` is the
  text's `y`.

The prompt pre-authorized a kit-input fix for the first row only. The second
row is a problem the plan did not see: with auto-fire, every drag meant to move
the cursor is a Fire rising edge on touch-down, so it confirms the highlighted
row first. With only the upper-tap fix, touch could reach nothing but default
rows. **Stopped and asked; Paul chose "drag + tap above".** Outside play,
auto-fire is off and a tap above the zone holds `fire`. That is kit-input
**0.4.0**: `configure()` for the two switches, and the `touchTapFire` source,
off by default, so play and any other host are unchanged.

**Readings taken, none a design call.**
- The cursor **clamps and skips disabled rows**. Wrapping would let a mouse
  flick land anywhere on the 41-row list.
- **Entry latch.** `syncScreen()` notices every screen change, including
  `killSkimmer()`'s, and the step after it latches held buttons and drops a
  queued Escape. That is what makes "inert during the freeze" hold for a press
  held across the freeze's end, not just one released inside it. It is also
  what keeps a fire-holding player's death from confirming RESTART.
- **Escape queues, never acts**, because named actions dispatch inside
  `sample()`, which runs in the freeze.
- **GDD §13's "Overdrive is the default highlight"** cannot apply while
  OVERDRIVE is locked. The cursor starts on CLASSIC.
- **Depth rows read "LEVEL n" / "BONUS b"**, rebuilt on entry, with a 7-row
  window that follows the cursor.
- **`quitToTitle()` overwrites with `newState()`**, per GDD §15.4's "before that
  function overwrites the state", so the title shows no stale board.
- **The harness gained `opts.spy`**, which wraps a function and counts its
  calls. H4 is asserted on `drawHud`'s call count per screen.

**Measured.**
- A keyboard tap's total rotate is **exactly ±1.0** at every tap length (1–7
  steps), so `MENU_ROTATE_STEP` 1.0 needs no epsilon. The test asserts all
  seven, both ways.
- **No baseline moved.** The hash and `GOLDEN_LANES` stayed green unedited.
- **Two closed files went red.** `test-cs003-p4.js`'s four `r` assertions were
  planned and rewritten in place. `test-cs008-p3.js` had three reds from a
