**The wrapper keeps line identity.** Each rewrite is one line for one line: an
`export const|function` loses its keyword, an `import { … } from` becomes
`const { … } = KitNames;`, and an `export { … } from` becomes a comment, with the
names read off the namespace in the `return`. So the test compares the inlined
body with its `lib/` file line by line, and every difference must be one of the
three rewrites. `KitProfile.NAME_CHANGE_NOTICE` is `KitNames.NAME_CHANGE_NOTICE`
itself, which is the reference identity the kit promises. The wrapper also
refuses a namespace import, a multi-line export, `export default`, a dynamic
`import(`, and an import from a module not inlined above it. Each is a fixture
in the test.

**The banner is a dash rule, not the module banner.** Seven closed tests slice
the built file on `// ={74} / // <file> / // ={74}`, and `test-cs002-p1.js`
checks that slicing both ways against `src/`. An equals-sign banner for
`lib/kit-names/kit-names.js` would read as a module that is not in `src/`. With
the dash rule the three bodies fall inside `20-achievements.js`'s slice. None of
those scans' banned tokens is in them (the plan's variant A, and green here).

**Store and profile are made in `Meta.boot()`, not when the script is
evaluated.** Evaluating the script touches no storage. `Store` is a `let`, null
until boot. A second `boot()` returns early, because two `KitStorage.create()`
calls over one keyspace have separate declaration tables (the kit calls that a
footgun).

**FINDING: `select()` after `createAnonymous()` is a no-op, and the plan
predicted otherwise.** The prompt says `createAnonymous()` then `select()` leaves
`lastUsed` naming the profile and a `playerId` minted. MEASURED: on an empty
install kit-profile's boot leaves `activeId` at the legacy id `p0`, and
`createAnonymous()` creates `p0`. `select("p0")` then hits `if (id ===
this.activeId) return true;` (`kit-profile.js:550`), which saves nothing and
mints nothing. The stored roster after boot had `"lastUsed":""` and
`"playerId":null`. The same holds for the non-ANONYMOUS id, because seq starts
at 0.
- **What the build does:** it keeps the `select()` as the prompt says, then calls
  `kit.current()`. The kit documents that call as a mint path, so the stored
  `playerId` is a v4 UUID at first boot.
- **What it cannot do:** store `lastUsed` without editing `lib/`, which is
  forbidden. Renaming `legacyProfileId` would make `select()` a real switch, but
  it would also move `p0` off the root store, which R12 and the GDD rely on.
- **Why the behaviour is unchanged:** a reload's `activateLoaded()` falls back
  to `roster[0]`, which is the same profile, and the test asserts that reload.
  The test asserts "selected" through `current()` and the reload, never through
  the `lastUsed` byte. Recorded for a kit reviewer in `kit-profile.NOTES.md`.

## P2 — what a profile keeps

**Built.** `settings` v1 (`{ controls: { mouse, touch, autofire, mirror, keys,
pad }, sound: { master, music, sfx, voice, track } }`, `track` by name),
`progress` `{ highestCleared }` and `telemetry` (`{ rows, wrapped }`, rows as
arrays), all through `Profiles.scope()` in `22-meta.js`. `23-main.js` hands
`Meta.boot()` `Game.settingsHooks`: `resetSettings()` (`resetControls()` +
`resetSound()`, writing nothing), `applySettings(data)` and `settingsSnapshot()`.
`Meta.saveSettings()` is called at five sites: the adjust step when the clamped
value moved, the mirror and auto-fire toggles, a capture that bound, and RESET TO
DEFAULTS. `21-telemetry.js` gains `snapshot()` / `restore()` and still names no
storage. `Meta.runEnded(outcome)` is a stub with no caller; its body is the
telemetry write.

**How the load is made per field.** `applySettings()` skips a field that is
missing or invalid, and Meta's `activateSettings()` calls `resetSettings()` first.
So "else default" is the reset's job, and the mutation that drops the reset is
exactly a bleed. Boot uses the same function: the reset there is a no-op over the
evaluation-time defaults. A binding page is checked whole: two slots per action,
not both null, a key a non-empty lowercase string and not `reservedKey`, a button
a whole number ≥ 0 and not Start, nothing seen twice. The kit's own setter then
runs inside a `try`. It refuses what the page check does not name (`gamepadleft`),
and a refused page stays at its defaults. MEASURED: dropping the game's duplicate
check leaves the duplicate cases green, because the kit refuses them too.

**Readings taken (Claude's; flagged in `STATUS.md`).**
- **`t` in play.** The prompt says both "write when capture turns off" and
  "never inside a play step". `t` in play is both. The play-step rule wins, so
  the toggle writes only off play, and the rows wait for the next seat
  (`autoPause`, a switch, the run's end). `autoPause` writes after `pauseRun()`,
  so its step is already a pause step. The mutant that writes at once is red.
- **The ring on a switch.** `beforeChange` writes the outgoing rows. `change`
  empties the ring, and with capture on it reads the incoming profile's rows.
  Without that, the next seat would write profile A's rows under profile B.
- **`Profiles.select(id)`** is added to the wrapper. It is the switch R11 wires,
  and the test's two-profile cases need it. `create` / `rename` / `remove` stay
  P4's, so the test plants a two-profile roster.
- **The telemetry read in play.** `t` turning capture on over an empty ring reads
  inside a play step. The rule forbids writes, and deferring the read would let
  the ring fill and then overwrite the stored rows.

**The closed file, in place.** `test-cs008-p7.js:436` now compares the stored

## P3 — the local top 10 and the run's end

**Built.** `createScores({ store, key, perMode, modes })` in `22-meta.js`, which
returns `qualifies` / `add` (rank or 0) / `list`, and its draft doc
`src/22-meta.NOTES.md`. It is created once, in `Meta.boot()`, over the root store
with `C.SCORES_PER_MODE` 10. `Meta.runStarted` / `benchUsed` / `eligible` /
`runOpen` / `runEnded` / `scores` / `lastPlace` are added; the run's record is
`Meta`'s closure (`run`, `placed`). The three seats are the last line of
`startGame()`, the first line of `quitToTitle()` (on pause), and `frame()` after
the step loop. The bench flag is at the top of `runAction()`. The title gets
SCORES as its third row, there is a new `SCREENS.scores` screen with
`buildScoreRows()`, and game over gets a third line. The harness exports
`Scores` and `createScores`. `test-cs011-p3.js` has 83 assertions. Build: 565.6
KB.

**Readings taken (Claude's).**
- **`runEnded()` does nothing when no run is open, the telemetry write
  included.** Without that guard, the game-over seat would write telemetry on
  every frame. The cost: a board started with `Game.reset()` and no
  `startGame()` opens no run, so quitting it from pause writes no rows. Every
  run a player can start comes through `startGame()`.
- **`Game.reset()` leaves the open run alone.** The plan gives the drop to
  `startGame()` only.
- **`modes` is the literal `["classic", "overdrive"]` in `Meta.boot()`**, not a
  `C` entry. It lists `state.mode`'s two values and is not a tunable.
- **`createScores` throws on an undeclared mode**, as kit-storage does on an
  undeclared key, and sorts on read with a stable sort, so a planted unsorted
  table loads in order.
- **A SCORES row has `action: null`.** Fire on it returns nothing, so it makes
  no sound and does nothing. Rotate scrolls.
- **Game over's third line is written in `draw()`** like its other two. It
  reads `Meta.lastPlace()`, a closure value, and does no storage read. SCORES'
  rows are built on entry, as the prompt says.

**MEASURED hazard: `frame()`'s text.** A comment saying "BEFORE audioFrame()"
inside `frame()` turned `test-cs009-p3.js` red ("frame() calls audioFrame()
exactly once"), because it counts that text. The comment now says "the audio
frame".
