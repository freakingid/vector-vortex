# log/CS009.md — The audio engine

Narrative build log for CS009: the engine and scheduler (P1), music-lab and two
tracks (P2), music in the game and the OPTIONS rows (P3), sfx-lab and the SFX
player (P4), the Classic SFX (P5), and the seventh soak plus the close (P6).
Each phase appends its reasoning here as it goes (`CLAUDE.md`).

## P1 — the engine

**What shipped.** kit-input 0.7.0 `onGesture`. kit-audio 0.1.0
(`createAudioEngine`, `createMusic`) in `16-audio-engine.js`. The two instances
in `19-sfx.js`. Five `C` keys. The harness's recording fake context behind
`buildGame({ audio: true })`. `test-cs009-p1.js` (165 assertions). No sound
plays: no track exists and no seat calls audio.

**Port source read at `5abd37a`** (`git show`, because the working tree may
move): `AudioSys` 1522–1553 and `MusicSys` 2173–2583 matched the plan's line
numbers. The track builders in between were read for shape only. None of them
was ported.

**Calls inside the plan's shape, none of them design:**
- **The gesture fires after the sink.** `keyDown()` / `setButton()` run first,
  so a throwing callback cannot eat the press. `unlock()` does not throw
  anyway: a context that fails to construct returns `false` and the game
  stays silent. **`touchcancel` got its own listener** because it shared
  `touchend`'s function, and a cancelled touch is not a player's gesture.
- **Bus levels at construction are a `.value` set, as in the source.** The
  "ramp, never a bare set" rule is about a *change*. Nothing is playing when a
  bus is built. `setVol` is the only writer after that, and the test asserts
  it writes no `.value`.
- **The tier refusal is two throws with two messages.** The range check
  (`1..4`) is permanent. "Tier not supported" is the line CS010 deletes when it
  ports the setter. There is no option flag: a flag would be a switch that
  CS009 has no use for.
- **The source's `"off"` became "any name with no track".** A kit cannot know
  the game's state names. For the source's own tables the behaviour is the
  same, because `off` was its only null track.
- **`scheduleStep` and `playNote` gained ctx guards.** `CLAUDE.md` says every
  audio entry point is guarded. They are exposed, and headless calls to them
  must not throw.
- **`MUSIC_TRACKS` is in `19-sfx.js`, as the prompt says.** Plan §2 and P2's
  prompt put it in `17-audio-tracks.js`, so P2 moves it (STATUS hazard).

**The stall resync, as built.** When `nextStepTime < now − lookahead`,
`missed = floor((now − nextStepTime) / stepDur)` is added to both the cursor
and the clock. The next step is then in `(now − stepDur, now]`, so the loop
schedules at most `ceil((lookahead + stepDur) / stepDur)` =
`ceil(lookahead / stepDur) + 1` steps. The first of them is clamped to `now`,
at most one step late. MEASURED: on the synthetic table (`stepDur` 0.17,
lookahead 0.20) the bound is 3. With the resync deleted, the same update
scheduled **353** steps.

**MEASURED vs PREDICTED.**
- Drift: every one of ~3,530 step start times is within 1e-6 s of
  `T0 + k × 0.17` over 36,000 frames, and so is the cursor. The plan predicted
  OO's −2.1e-11 would carry over, and it did.
- Plan §1.7 predicted that an opt-in fake changes no closed test. MEASURED: 43
  closed files green, and `test-cs006-p2.js` reads **1229033515**.
- The synthetic table's worst step is 14 nodes (lead 5 + bass 2 + hat 3 +
  pad 4), under the ceiling of 16. That is a fixture count, not a track's.
  P2's tracks are the real test of the ceiling.

**A test trap found by mutation.** The first stall assertion counted
*distinct start times*. With the resync deleted it stayed **green**, because the
burst clamps every missed step to the same instant, so 353 steps read as one.
The count is now the lead layer's notes (a note on every step). A later test
that counts steps must do the same.

**Mutation record — 6 of 6 red after the fix** (each applied to `src/`, built,
run, reverted):

| # | Mutation | Red on |
|---|---|---|
| M1 | resync `if` → `if (false)` | "schedules 1..3 steps (got 353)" |
| M1b | resync advances the clock but not the cursor | "keeps bar phase (got 13, want 12)" |
| M2 | `scheduleStep` skips layer 2 | the layer's note count (0 of 883), the node count (11 not 14), the noise buffer |
| M3 | `scheduleStep` skips `audition === "fail"` | as M2, plus "never reads a layer's audition" and the source scan |
| M4 | `setVol` writes `.value` instead of ramping | three-call automation, the ramp target (four buses) |
| M5 | `touchstart` calls `onGesture` | both touchstart cases, and "create no context" through the game's input |
| M6 | the noise buffer uses the platform generator | both noise-equality assertions and the built-file scan |

## P2 — music-lab and the two tracks

**What shipped.** `tools/music-lab.html` (46 KB). `src/17-audio-tracks.js`
(`buildTitleTrack`, `buildPulseTrack`, `MUSIC_TRACKS`, and three helpers:
`midiHz`, `trackRow`, `trackNote`). `MUSIC_TRACKS` moved out of `19-sfx.js`.
The registry's `tracks` went 0 → 2. `test-cs009-p2.js` has 64 assertions. No
baseline moved.

**The lab's shape, taken from Orbital Overhaul `5abd37a`, with none of its data
or names.** The source had a lab-only copy of the scheduler (BLOCK A) and the
builders (BLOCK B). Here **both blocks are whole files**, so the identity test
compares whole files and COPY TABLE prints something to paste over the whole of
`17-audio-tracks.js`. No helper, layer name or builder name is the source's.
The source's `mk`, `put` and `hit` became `trackRow` and `trackNote`. A noise
cell carries `f` 440, because the test requires every `f` to be > 0 and the
source used 0.

**Calls inside the plan's shape, none of them design:**
- **SOLO is two nodes, not one.** `layerSink` returns a mute gain feeding a solo
  gain, and `gateLevels()` is a pure function the test runs. Mute outranks solo
  on the same layer.
- **The A/B/C marks live in the lab UI** (`LAB_TRACKS.sections`), not in the
  track data. A `sections` field would ship bytes the game never reads.
- **COPY TABLE rewrites only what changed since load**, so an untouched
  `gain: 0.075` is never re-printed as a different string. It throws on an edit
  that names no layer, rather than printing an unedited table.
- **The ribbon seeks on click** by writing `step` and `nextStepTime` on the
  lab's own `createMusic` instance. On a 108 s track, reaching C otherwise
  takes 72 s.
- **Restart names a silence first** (`"lab-silence"`), because `setState` does
  nothing when given the name already playing.

**How `pulse` was built** (E minor, 80 BPM, `stepDur` 0.1875, 16 steps a bar,
36 bars = 108 s):
- **A (bars 0–11).** Em Cmaj7 G D twice, then Am7 Cmaj7 Em D. The tune sits
  E4–G5. Its motif is E5 D5 B4 (a dotted quarter, an eighth and a half note),
  then G4 B4 E5 rising over Cmaj7. Heart is once a bar, and ticks start at bar
  4, so the track opens on four instruments.
- **B (bars 12–23).** Cmaj7 D Bm7 Em Cmaj7 D G G Am7 Bm7 Cmaj7 D. The tune goes
  up an octave (to B5), the swell's two notes swap order, the bassline adds its
  octave and fifth, and the heart doubles.
- **C (bars 24–35).** Em D Cmaj7 G Am7 Em Cmaj7 D, then Em Cmaj7 Am7 **B**. The
  bassline is busiest here, with six notes a bar, and so are the ticks. The
  cycle runs up and down. Bar 32 restates bar 0's motif exactly, and the B
  major bar ends on D#5, which resolves to bar 0's E5 at the loop.
- **Why each layer passes solo (the target, not the verdict).** `melody` is the
  tune. `swell` is a two-note-a-bar chorale line (G B | C B | D B | A F#).
  `bassline` is a rhythm on the root, with a different figure in each section.
  `cycle` puts three chord tones against eight eighths, so the figure shifts
  within each bar. `heart` is lub-dub. `tick` is a syncopated figure that never
  falls on a downbeat.

**How `title` was built** (G major, 60 BPM, `stepDur` 0.25, 8 bars = 32 s). A:
G Em C D, with a four-bar theme that settles on A over D. B: G Bm C D, which
climbs to G5 and falls to F#4, and that note leans into bar 0's G. Besides the
theme there are three layers. `bells` plays a four-note falling chord figure on
every bar's second half, two octaves up. `glow` is a two-note chorale line.
`ground` plays the root for three beats and the fifth on the fourth.

**MEASURED, and how.**
- **Nodes per step**, counted on the recording fake (`scheduleStep` over every
  step). `title` worst 9, at step 0. `pulse` worst **14**, at step 0 (melody 3,
  swell 4, bassline 2, cycle 3, heart 2), on 56 of 576 steps. The ticks were
  kept off step 0 to hold that. The ceiling was not approached.
- **A consonance probe** (a session script, not committed) listed every onset
  where two layers sound a semitone, a minor ninth or a tritone apart. The
  first draft had rubs: cycle's F#4 against the tune's G4 over Em, and cycle's
  B3 against swell's C4 over Cmaj7. Cycle's tones changed to Em7 (E B D),
  Cmaj7 (C G E) and G (G D B), and that left **no semitone rubs**. The 19 flags
  that remain are all Cmaj7's major seventh, which is intended.
- **Levels: an offline render in headless Chromium** (Playwright's bundled
  build, driven over CDP). Each table was rendered whole and one layer at a time
  through BLOCK A into an `OfflineAudioContext`. On the first draft, the pads,
  bells, cycle and tick sat 12–20 dB RMS under the tune, which is too quiet to
  judge solo. Gains changed in the lab: swell and glow 0.030 → 0.085, bells
  0.030 → 0.075, cycle 0.030 → 0.055, tick 0.020 → 0.050, bassline 0.110 →
  0.098, ground 0.100 → 0.090. After the change, in dB RMS: `pulse` melody
  −28.7, bassline −27.9, cycle −36.1, heart −36.5, swell −37.1, tick −48.1.
  `title` theme −28.6, ground −28.5, glow −36.9, bells −41.0. Mix peak is 0.30
  (`pulse`) and 0.32 (`title`).
- **The lab in a real browser, from `file://`** (the same CDP driver): six
  rows and six SOLO buttons; Play creates a context; SOLO on layer 0 plus MUTE on
  layer 2 settle the gates to [1,1], [1,0], [0,0], … ; a click at 70 % seeks to
  bar 26, section C; COPY TABLE writes `audition: "pass"` and `gain: 0.050`;
  switching to `title` gives four rows; Stop fades to silence. There were no
  exceptions. Headless Chromium never resolves `navigator.clipboard`, so the
  status line says "select the text below" until the clipboard answers.

**PREDICTED, not measured:** whether any layer passes Paul's solo listen. A6
makes that his, in the lab, whenever he chooses.

## P3 — music in the game, and the OPTIONS rows

**What shipped.** `musicStateFor()` and `MUSIC_SILENCE` in `19-sfx.js`.
`audioFrame()` in `Game.frame()`. `C.MODE_TRACK` and `C.MUSIC_TRACK_CHOICES`.
Five OPTIONS rows after CREDITS, with `sound` / `resetSound()` / `ADJUST` /
`refreshSoundRows()` in `23-main.js`. Two harness exports.
`test-cs009-p3.js` has 184 assertions. `test-cs008-p6.js`'s three assertions were
rewritten in place. No baseline moved: `test-cs006-p2.js` still reads
**1229033515**, and 46 files are green.

**Calls inside the plan's shape, none of them design:**
- **`musicStateFor` lives in `19-sfx.js`, top-level**, so the harness can
  export it and the test can drive it without a frame. It reads only `C`. The
  silence is the name `"off"`, which names no track and is `createMusic`'s own
  starting state. The first headless frame is therefore a no-op, not a change.
- **One row mode, not a second one.** `adjusting` holds a key into `ADJUST`,
  and each entry carries `lo`, `hi`, `get` and `set`. The two sensitivity rows
  moved onto it too (action `adjust`, with the row's `adjust` field), because
  the prompt says generalise, and a second branch would be a second mechanism.
  ⚠ **One behaviour change:** `set` runs only when the clamped value moved. A
  sensitivity tap past its clamp used to call `configure()` with the same value
  again. That is idempotent, and no closed test saw it. For a volume, it means
  a tap at the clamp schedules no ramp (M9).
- **`resetSound()` calls `setVol` on all four buses.** Headless that holds the
  level. With a context it ramps back to unity. `resetControls()` (RESET TO
  DEFAULTS) does not touch sound: that row is on the Controls page.
- **The details are written on every OPTIONS step**, beside the telemetry
  detail, so the step that arms a row already shows `‹…›`.

**The closed-file rewrites (plan §1.8), each restoring its precondition:**
1. The row list is read by drawing at each cursor position down the ten rows,
   and the cursor comes back to TELEMETRY. The assertions after it need the
   cursor there.
2. "No Sound or Music row" became "the five rows are present", read from the
   same scroll.
3. "Four rows carry a detail" became "every drawn row but BACK carries a
   detail". The window at cursor 0 draws seven rows, and all seven have one.

MEASURED before the rewrite: exactly those three failed (3/254), as plan §1.8
predicted. No other closed file went red.

**Test traps found while writing it (the test's bugs, not the build's).**
`rec.clear()` wipes `connections`, so the "voice feeds master" check has to
run before any clear. The file now never clears and counts by slice. The bus
build at `unlock()` is a bare `.value` set (P1's documented reading), so "never
a bare set" counts from before the taps. `frame()`'s source slice has to stop at
`function audioFrame()`, or it counts the definition as a second call.

**PREDICTED, not measured:** that the crossfade at RESTART is heard as intended.
The fake confirms the ramps, not the sound.

## P4 — sfx-lab, the SFX player, C.SFX

**What shipped.** `createSfxPlayer(engine, { noise })` and `sfxCheckRecipe()`
in `16-audio-engine.js`, which is now kit-audio **0.2.0** (`.NOTES.md` entry).
`Sfx` in `19-sfx.js`. `C.SFX` (21 recipes) and `C.SFX_KILL_PITCH` (seven
voices) as a new SFX config group. `tools/sfx-lab.html`. Three harness exports.
`test-cs009-p4.js` has 168 assertions. No seat plays anything, and no baseline
moved.

**Calls inside the prompt's shape, none of them design:**
- **The signature takes `{ noise }`.** The prompt writes `createSfxPlayer(engine)`
  and "the injected noise generator only". The engine carries no generator, so
  the player takes one the way `createMusic` does. `Sfx` passes a second
  `mulberry32(C.AUDIO_NOISE_SEED)` instance. It shares no draws with the music
  buffer or with the run, so no new seed was added.
- **`play` takes `when` as well as `pitch`.** It is an absolute context time.
  The lab uses it to sequence "in context" without a timer. It is additive and
  defaults to now.
- **A recipe with an unknown field throws**, as the track loader refuses `tier`.
  Validation runs before the ctx guard, so a bad table fails headless too.
- **`hold().set(t01)` interpolates exponentially** (`f · (to/f)^t`) with
  `setTargetAtTime`. It is equal steps in pitch, and it does not zipper at a
  frame rate.
- **BLOCK SFX is the group's text, header comment included.** The group runs
  from its `// ---- SFX` line to the next group header. COPY OUT replaces only
  the lines of events whose pick is not A. All-A reprints the block byte for
  byte, and the test asserts that explicitly.
- **The lab carries BLOCK B whole** rather than `pulse`'s builder alone. The
  builder needs the file's helpers, and a whole-file identity is the rule
  music-lab already uses.
- ⚠ **`surgeCharge` A peaks at 0.45.** MEASURED (node over the built
  `MUSIC_TRACKS`, working tree on `88befdb`): the loudest summed step peak is
  0.434 on `pulse` and 0.242 on `title`. The gain was set to pass P5's 0 dB
  gate. That is a prediction about the gate, not a measurement of it.

**The two-file edit became three.** `16-audio-engine.js` now lives in both labs,
so the P4 edit re-copied music-lab's BLOCK A. `test-cs009-p1.js`'s version pin
was rewritten in place, from 0.1.0 to 0.2.0. MEASURED before either fix: exactly
those two assertions were red across the suite.
