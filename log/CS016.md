### Two seats the plan's text did not name, and why they are not design

Both were forced by an ANSWERED behaviour meeting a seat the plan named; neither
changes what the game does.

1. **The scan runs in the Dive's branch too.** Plan §3 seats `promptScan()`
   after the filters and before `updateSpawner()`, and N2 row 9's trigger is
   `state.dive.active` with rings laid. `update()` returns from the dive branch
   ABOVE that seat, and a dive ends in `resetDive()` on its last step, so at the
   named seat `dive.active` is never true — row 9 would never fire. The dive
   branch calls the same scan after `updateDive()`, with
   `WELLS[state.wellIndex]` (the dive's last step has already entered the next
   well). A step reaches exactly one of the two, so "one fire per step" holds.
2. **`promptStep()` sits ABOVE the dive branch**, not beside the scan (plan
   §3's wording): N4's answered behaviour is "a pause holds a prompt and a dive
   continues it", and beside the scan it would never run on a dive step.

### "saveTelemetry()'s four seats" — the plan's list, not the function's

`saveTelemetry()`'s real callers are `runEnded()`, `beforeChange`, `autoPause`
and `toggleTelemetry()` (capture turned off, off play). The plan and the prompt
name the four seats as the clear edge, `runEnded()`, `autoPause` and
`beforeChange` — the clear edge instead of the toggle. P1 built the prompt's
explicit list. The toggle is not a seat for the marks; the clear edge is,
because it is the one play step the pin (`test-cs015-p2.js:431`) exempts.
`savePrompts()` writes only when a mark is unsaved, so a session that has seen
everything writes the key never again.

- **"Stops reading the board once every row is seen"** is structural: the size

  Asserted with a Proxy that counts property reads (0 with all seen, >0 with one

- **Row 12's counter** is `Meta.unlocks()`, the count `sounded()` sounded since
  this profile was activated — reset beside the seen set in `loadPrompts()`, so
  a switch never hands one profile's unlock to another. An unlock at the run's
  end fires the row on the next run's first play step.
- **Rows 8–11 need no mode test**: each reads something only an Overdrive
  schedule releases (a token, a laid ring, a Warden, a Mimic); a bench key that
  puts one on a Classic board fires the row, as a bench Carrier does. Row 12

  CS017's allocation measurement (F4) may want to see.
- **`promptReset()`** is `startGame()`'s one line; `Game.reset()` does not
  touch the queue (nothing asked it to, and every closed test starts a run).
- **Only `activateSettings()` gained a line** (`loadPrompts()`), so boot and a

### The seats, as built

- **Idle clock** — the menu branch's foot, after every title refresh line:
  `attractIdle += dt` on a title step whose struct is at rest and on which
  `runAction()` did not run (`acted`, cleared just before `input.sample()`);
  anything else zeroes it. It reads no clock (MEASURED: `Date.now` frozen for
  the whole idle and never read, and the demo still came at 20 s of frames).
  1200 steps of `1/60` reach 20.0 from below; the demo came on the step the
  sum crossed it (≤ 61 steps after 19 s in the test).
- **Start** — `startAttract()` calls `startGame(C.ATTRACT_SEED, { mode, startDepth,
  attract: true })` and then sets the flag; `startGame()` reads `opts.attract`
  into a local and skips `lastRunMode` and `Meta.runStarted()`. `promptReset()`
  still runs: emptying a queue is not a write and the demo's queue must start
  empty.
- **Driver** — `input.sample(dt, state.input); if (attract) attractInput();` on
  one line. `attractInput()` reads the sampled four fields first; any non-rest
  value ends the demo; otherwise `attractDrive()` overwrites them.
- **Skips** — `Telemetry.sample()`; `scanPrompts()` (the wrapper, so both of
  P1's seats go with one line); the clear edge's three calls in one
  `if (!attract)` block. The tally, the bonuses and the dive still run: they are
  the demo's own `state`.
- **Endings** — `runAction()`'s first line after `acted = true`; the struct test
  in `attractInput()`; `frame()`'s seat after the `'died'` line for the demo's
  game over and `ATTRACT_LENGTH` (`state.time`, simulation seconds), before
  `audioFrame()` and `draw()`, so no frame paints the game-over screen.
  `quitToTitle()` clears the flag itself, so every ending — a test's direct call
  included — ends it; `Game.reset()` clears the flag and the idle clock.
- **Line** — `draw()`: `if (attract) drawAttractLine(ctx); else if (play or
  pause) drawPrompt(...)`. Same band, `PROMPT_COLOR`, no fade.

### ⛔ A defect the plan predicted away, MEASURED red and fixed

N9 predicted "the title's entry step latches whatever is held, so the ending
press confirms no row." **False as written for an ending inside a step.** The
struct-reading ending (and a named action, both inside `update()` before its
second `syncScreen()`) makes THIS step the title's entry step, and
`quitToTitle()` re-mints `state` from `newState()` — `state.input` included. The
entry step latched a fresh at-rest struct, and the Fire that ended the demo
was a rising edge on the next step: PLAY confirmed, screen `mode` (MEASURED, the
test's first run). A normal QUIT TO TITLE never meets this because it happens
in a menu step and the entry step is the NEXT update, which samples first.
Fix: `endAttract()` keeps the step's struct object across `quitToTitle()`
(`state.input = held`). `frame()`'s seat needs none of it (the next step
samples before its entry step) and calls `quitToTitle()` directly. The
mutation is in the test.

### Calls inside the answers

- **The Purge period** — N6 says "a Purge every N seconds ⚠" and names no N.
  A tunable must be in `C`, so `C.ATTRACT_PURGE_EVERY` **5.2 s ⚠** (the soaks'
  hunter pressed every 311 ticks, 5.18 s). One press per period, never at
  `t = 0`: `time >= P && time % P < FIXED_DT`. Recorded in `STATUS.md`.
- **The steer** — the hunter taps arrow keys past a 0.3-lane deadband; the
  driver writes `rotate` directly, so it moves the whole delta clamped to
  `KEY_SPEED_MAX × FIXED_DT` (the keyboard's top speed) and needs no deadband
  constant. The wall pin and the stop are the soaks' fixtures and were not
  ported.
- **The seed** — N7: "a fixed integer ⚠". MEASURED over ten seeds, the shipped
  driver at depth 5 for 45 s: every one cleared two wells, took all six rings
  in both dives and died nowhere; `20260923` (first pick) showed four kinds and
  no Reaver, `1` showed five with tokens on screen 359 steps. **`1` shipped.**
- **"ANY KEY"** — the struct and `onAction` are N9's two readings, and an
  unbound key reaches neither: `q`, Enter or Tab do not end the demo while the
  line says ANY KEY. `onGesture` (the audio unlock) sees every key, but using
  it would be a third ending the answer did not name. **Surfaced, not built**
  (`STATUS.md`). ✅ **Paul, 2026-09-23: reword it** — `DEMO — PRESS FIRE`
  (`D` was considered: bound only as a rebindable second RIGHT key, and no pad
  or touch player has it).
- **A device reading during a demo DEATH FREEZE** — `frame()`'s freeze branch
  samples without `update()`, so a mouse move there is drained and lost; a held
  button survives the freeze and ends the demo on the first live step; a named
  action ends it at once (`runAction()`). No shipped demo dies (measured), so
  this is reachable only on a mutated length.
